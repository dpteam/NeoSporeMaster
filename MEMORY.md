# MEMORY.md — память проекта

Этот документ хранит **принятые решения**, **почему** они приняты и **что дальше**. Он нужен,
чтобы контекст не терялся между сессиями работы.

---

## 1. Ключевые решения

### 1.1. Полная переработка, а не заплатка
Старый SporeMaster 2.0 — это WPF-приложение под .NET Framework с зависимостями
(`ICSharpCode.TextEditor`, `3DTools`, `VTreeView`). Вместо точечного «оживления» решено
перенести логику в чистое ядро под .NET 9 и сделать его headless, а интерфейс — наращивать поверх.

### 1.2. Ядро + CLI + тесты, GUI позже
Пользователь просил тесты «как-то headless и/или CLI». Поэтому в первую очередь реализованы
`SporeMaster.Core` и `SporeMaster.Cli`. GUI-проект (миграция WPF на `net9.0-windows`) отложен.

### 1.3. Без сторонних библиотек
Всё на BCL: собственный парсер аргументов, собственный тест-раннер, `System.Buffers.Binary`
для little-endian. Это упрощает сборку и соответствует требованию «всё нативно».

### 1.4. Источник истины по форматам — `refs/`
Реальные архивы (`refs/_PackageFilesBetaVer`, `refs/_PackageFilesFinalVer`) используются в тестах
как эталон. Реализации в `refs/SporeModder-FX-master`, `refs/CheckAll`, `refs/SporeEdit`,
`refs/EAPackageBrowser-main` — справочные.

### 1.5. Хеш именования ≠ ID типов/свойств
Важный вывод: FNV-хеш используется для **имён групп и инстансов** (в `reg_file.txt` строки без
явного хеша означают «ID = FNV(имя)»). А идентификаторы **типов** и **свойств** — это константы,
присвоенные EA: например, у `description` и `parent` ID идут подряд (`0x00B2CCCA`, `0x00B2CCCB`),
что доказывает отсутствие хеширования. Поэтому:
- `Fnv.Hash("prop") = 0x74DA5446`, но реальный тип `.prop` в игре — `0x00B1B104`;
- реестры (`reg_type.txt` и др.) — это таблица соответствий «имя ↔ ID», а не результат хеша.

### 1.6. Устойчивость к ошибкам
Парсер никогда не бросает исключение на «нашем» формате: вместо этого копит `Diagnostic`
(Info/Warning/Error) и продолжает. Исключение — только `NotAPackageException`, когда данных
не наш формат.

## 3. Дорожная карта (что делать дальше)

Приоритет сверху вниз.

1. **Текстовый формат свойств (`.prop` / ArgScript)** — сейчас `.prop` читается/пишется как
   бинарный блоб. Нужен человекочитаемый формат, как в SporeModder FX
   (`refs/SporeModder-FX-master/src/sporemodder/file/prop`).
2. **Локали (`locale`, STBL)** — разбор и сборка таблиц строк; автоматическая генерация
   `auto_*`-локалей (как делал SporeMaster 2).
3. **Текстуры (DDS / `raster`)** — конвертация и упаковка изображений.
4. **Модели RenderWare4** — перенос `RW4Model`, `ModelPack/Unpack`, `OgreXml*` и `DecodeRW4`.
5. **GUI** — миграция WPF на `net9.0-windows` (или новый UI), переиспользуя `SporeMaster.Core`.
6. **Хеш-гуссер** (`guess_left.txt` / `guess_right.txt`) — восстановление имён по хешам.
7. **Индекс для полнотекстового поиска** (`FullTextIndex`).
8. **Скрипты/конвертеры** из `refs/SporeModder-FX-master` (cnv, tlsa, spui, effect и т.д.).

## 5. Технические заметки

- **RefPack** портирован с сохранением оригинальных «странностей» (в т.ч. тройное чтение одного
  байта в хеш-функции компрессора) — чтобы вывод совпадал со SporeModder FX.
- **Индекс DBPF** описывается тремя битами «общее/по-элементно» для полей type/group/unknown:
  - бета Spore: тип индекса `0x06` (общие group и unknown);
  - релиз: тип индекса `0x04` (общий только unknown).
  Парсер поддерживает любую комбинацию 0..7.
- **Заголовок**: `indexMajor` @0x20, `indexCount` @0x24, `indexSize` @0x2C,
  `indexMinor` @0x3C, `indexOffset` @0x40. Для DBBF `indexSize` и `indexOffset` — 64-битные.
- **Смещение по умолчанию при записи** — DBPF 2.0 (совместимо с классическим SporeMaster).
