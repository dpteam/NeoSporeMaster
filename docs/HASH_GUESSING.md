# Восстановление имён по хешам (hash guesser)

Документ описывает, как SporeMaster 3 восстанавливает имена ресурсов по их 32-битным хешам.

## 1. Зачем это нужно

В `.package` группы и инстансы именуются 32-битными хешами (`FNV`). Основной реестр
`reg_file.txt` знает большинство имён игры, но у модов и пользовательских ресурсов имена могут
быть неизвестны. Их можно попытаться «угадать», разложив имя на фрагменты.

Кроме того, FNV-хеши имеют коллизии, поэтому у одного хеша иногда есть несколько возможных имён.

## 2. Реверс FNV

Хеш Spore — это FNV-1 (`h = h*prime ^ c`), и его можно частично обратить. У шага хеша есть
мультипликативный обратный элемент `fnv_unstep = 0x359C449B` (такой, что
`0x1000193 * fnv_unstep ≡ 1 (mod 2^32)`). Значит, зная хвост имени, можно «отнять» его:

```
UInt32 FnvReverse(UInt32 h, string tail) {
    for (i = tail.Length-1; i >= 0; i--) { h ^= lower(tail[i]); h *= fnv_unstep; }
    return h;
}
```

## 3. Алгоритм

Имя представляется как `prefix + L + contains + R + suffix`, где:

- `prefix`, `suffix`, `contains` — подсказки пользователя (могут быть пустыми);
- `L` — фрагмент из `guess_left.txt`;
- `R` — фрагмент из `guess_right.txt`.

Для целевого хеша:

1. `th = FnvReverse(target, suffix)` — убираем известный хвост.
2. Строим таблицу `left_hash: FNV(prefix + L) → L` для всех левых фрагментов.
3. Перебираем все правые фрагменты `R`:
   - `h = FnvReverse(th, R)`;
   - если `contains` непусто, `h2 = FnvReverse(h, contains)`, иначе `h2 = h`;
   - если `h2` есть в `left_hash`, получаем имя `prefix + L + contains + R + suffix`.
4. Каждого кандидата проверяем прямым хешированием (защита от ошибок и лишних срабатываний).

Сложность на один хеш — порядка `|R|` операций с обращением к словарю, что даёт десятки
миллисекунд на миллионе фрагментов.

Есть и итеративный режим (`--iterative`): найденные имена используются как `prefix` для
следующего раунда, что позволяет собирать более длинные имена из нескольких фрагментов.

## 4. Словари

`guess_left.txt` (~250 тыс. фрагментов) и `guess_right.txt` (~1 млн фрагментов) лежат в `data/`.
Они **не** встроены в сборку (это ~20 МБ); `SporeMaster.Core` помечает их как контент, который
копируется в выходную папку, и загружает с диска по требованию. Поиск идёт по:

1. каталогу из `--dict <dir>`;
2. текущему каталогу;
3. каталогу сборки;
4. подпапкам `data/` вверх по дереву (там оказывается `data/` репозитория).

## 5. CLI

```powershell
# Один или несколько хешей
dotnet run --project src/SporeMaster.Cli -- guess 0x73BF81A5

# С подсказками и явным каталогом словарей
dotnet run --project src/SporeMaster.Cli -- guess 0x... --prefix my --suffix car --contains _training_ --dict data

# Итеративный режим (имя из нескольких фрагментов)
dotnet run --project src/SporeMaster.Cli -- guess 0x... --iterative

# Угадать имена для всех «безымянных» хешей в архиве
dotnet run --project src/SporeMaster.Cli -- guess --package <архив.package> --limit 200
```

## 6. Пример

Хеш `0x73BF81A5` восстанавливается как `creatur_massiverock1_pile` (первый результат; далее
идут возможные коллизии).
