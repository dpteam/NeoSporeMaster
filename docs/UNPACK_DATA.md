# Экспериментальная распаковка в `Data`

Документ описывает экспериментальный режим **полной распаковки архива в игровой вид** (`Data`),
который максимально приближает результат к тому, как данные лежат в самой игре.

## 1. Зачем

Обычный `unpack` раскладывает ресурсы как `group/name.ext` (папка = группа, имя = инстанс).
Это удобно, но не совпадает с настоящей структурой игры. Экспериментальный режим использует
**карту ключей игры** (`KeyMap.txt`), чтобы восстановить **реальный путь** каждого ресурса
(например `Arenas\Editors\ce_editor_background_sporepedia.gmsh`).

Это нужно, чтобы:
- понимать устройство данных по файлам (какие каталоги/имена реальны);
- готовить почву для полноценной распаковки/упаковки «как в игре»;
- сверять наши имена с игровыми.

## 2. Как работает

```powershell
dotnet run --project src/SporeMaster.Cli -- unpackdata <package> <output-dir> --keymap <KeyMap.txt>
```

Для каждого ресурса:
1. ключ `(type, group, instance)` ищется в `KeyMap`;
2. если найден — используется **точный реальный путь** из карты;
3. если нет — фолбэк на `group/name.ext`.

Ресурсы пишутся **как есть (байты)**, без конвертаций — так они и лежат в распакованном `Data`.

## 3. Проверенный результат

На `Spore_Game.package` (11676 ресурсов) с картой ключей `SporeBeta2008/Data/KeyMap.txt`:

| Источник имени | Ресурсов |
|----------------|---------:|
| из карты ключей | **6793** |
| фолбэк `group/name.ext` | 4883 |

То есть даже между **бета-** и релизной версиями общие хеши позволяют восстановить реальные имена
для ~58 % ресурсов. Получившаяся структура — настоящие игровые каталоги:
`AbilityTemplates`, `achievements~`, `adventure~`, `animations~` и т.д.

## 4. Связь с `DDFList`

В распакованном `Data` каталоги, входящие в сборку, описаны в файлах `*_DDFList.txt`
(`#include` других списков). Они определяют, что видит игра/редактор в «unpacked» режиме и что
попадает в сборку. В будущем это используется для выборочной/полной распаковки по секциям.

## 5. Ограничения (эксперимент)

- Фолбэк для неизвестных ключей даёт `group/name.ext`, а не реальный путь.
- Локали/инстансы могут требовать особого обращения (`!`-имена в карте ключей).
- Итоговый каталог пока пишется напрямую в `<output-dir>` (без подпапки `Data`); при интеграции
  с тест-контуром игры подпапка будет добавлена.
