# AGENT.md — правила работы над SporeMaster 3

Этот документ описывает, **как** следует вносить изменения в репозиторий — людям и ИИ-агентам.
Соблюдение этих правил обязательно, чтобы проект оставался собираемым, тестируемым и понятным.

> **Если контекст потерян / чат сбросился — начни с `RESUME.md`** (шпаргалка: команды, карта
> репозитория, текущее состояние, грабли, что дальше).
>
> **Держи `RESUME.md` актуальным**: после крупных изменений обновляй в нём разделы 5 (снимок
> состояния) и 7 (что дальше), а также счётчик тестов.

## 1. Базовые принципы

1. **Только .NET 9.** Все проекты нацелены на `net9.0`. Обновлять `TargetFramework` без причины нельзя.
2. **Без сторонних библиотек.** Разрешён только BCL (.NET). Никаких NuGet-пакетов
   (в том числе для тестов и парсинга аргументов) — пишем сами.
3. **Устойчивость к ошибкам.** Любой парсер внешних данных (архивы, файлы реестров) обязан
   работать «динамически отказоустойчиво»: при повреждённых данных — писать диагностику и
   продолжать, а не падать. Исключения — только для «это вообще не наш формат».
   - В **ядре** — `DiagnosticSink` (Info/Warning/Error), а не исключения.
   - В **CLI** — каждое действие в `try/catch`, ошибка печатается и возвращается код выхода.
   - В **GUI** — каждый обработчик события обёрнут в `Guarded(...)`; в `App` стоит глобальный
     обработчик `DispatcherUnhandledException` (пишет `%TEMP%\sporemaster-gui-crash.log` и
     продолжает работу). Ошибки декодирования изображений/превью не должны ронять окно.
   - **GUI-проект обязан собираться с `InvariantGlobalization=false`**: WPF разрешает культуры
     привязок через `System.Globalization`, и при инвариантной глобализации падает на
     `XmlLanguage.GetSpecificCulture()` («Cannot find non-neutral culture related to 'en-us'»)
     при отрисовке `GridView`.
4. **Проверяемость.** Изменения в ядре сопровождаются тестами, которые можно запускать
   headless (без GUI).
5. **Документация — на русском, интерфейс программы — на английском.** Строки CLI — на английском,
   и должны браться из `Localizer` (см. `src/SporeMaster.Core/lang/en.lang`).

## 2. Структура и стиль кода

- Проекты и пространства имён: `SporeMaster.Core`, `SporeMaster.Cli`, `SporeMaster.Gui`,
  `SporeMaster.Tests`.
- Логика форматов живёт только в `SporeMaster.Core`. GUI и CLI — тонкие оболочки над Core;
  UI-независимые данные (сессии, превью) — в `Core.Presentation`.
- Публичные типы оформляем XML-комментариями (`/// <summary>`), язык комментариев — английский.
- Соблюдаем стиль окружения: `file-scoped namespace`, `var` где очевидно, `ArgumentNullException.ThrowIfNull`,
  записи (`record`) для маленьких неизменяемых структур.
- Файл — одна логическая сущность. Имена файлов = имена типов.
- Никаких «магических чисел» без пояснений: константы выносим в `DbpfConstants` и т.п.

## 3. Работа с форматами

- Источник истины по форматам — код в `refs/` (SporeModder FX, SporeEdit/Gibbed, CheckAll,
  EAPackageBrowser) и реальные архивы в `refs/_PackageFilesBetaVer` / `refs/_PackageFilesFinalVer`.
- **Нельзя ломать совместимость**: правки в DBPF/RefPack должны проходить на реальных архивах
  (тесты `RealPackageTests`, `DbpfRoundTripTests`, `RefPackTests`).
- Загадочные поля формата не удаляем «как мусор» — помечаем комментарием и сохраняем при
  round-trip (см. `DbpfEntry.Unknown`, `Flags`).

## 4. Тесты

- Тест = публичный статический метод с атрибутом `[SporeTest("имя")]` в проекте `SporeMaster.Tests`.
- Утверждения — через `Assert` (собственный раннер), без внешних фреймворков.
- Тесты на реальных данных обязаны **корректно пропускать проверку**, если данных нет
  (не падать с невнятной ошибкой).
- Запуск: `dotnet run --project tests/SporeMaster.Tests -c Release` (можно `--filter <подстрока>`).

## 5. Коммиты и история

- История изменений фиксируется в `HISTORY.md` (человекочитаемо, на русском).
- Долгосрочные решения и «почему так» — в `MEMORY.md`.
- Сообщения коммитов — краткие, в повелительном наклонении; язык — русский или английский,
  главное — единообразие внутри коммита.

## 6. Границы

- Не трогаем `refs/` (это справочные материалы и тестовые данные).
- Не трогаем `SporeMaster/` (легаси-исходники) без явной необходимости — это ориентир для сверки.
- Не добавляем секреты, локальные абсолютные пути, артефакты сборки (`bin/`, `obj/`) в репозиторий.

## 7. Чек-лист перед завершением изменения

1. `dotnet build SporeMaster3.sln -c Release` — без ошибок и предупреждений.
2. `dotnet run --project tests/SporeMaster.Tests -c Release` — все тесты зелёные.
3. Для изменений в GUI: `dotnet run --project src/SporeMaster.Gui -- --selftest <архив.package>`
   и убедиться, что отчёт заканчивается на `RESULT: OK`.
4. Обновлены `HISTORY.md` (и при необходимости `MEMORY.md`, `README.md`, `RESUME.md`).
   При росте версии — обновить `<Version>` в `Directory.Build.props` (единый источник; видно в
   `spore --version`).
5. Новые строки интерфейса добавлены в `en.lang`, если они видимы пользователю.
